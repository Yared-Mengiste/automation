# PDF character replacement architecture

`app.py` authenticates the admin or creator and provides Generate, Characters, shared Job History, and admin Account Status. Password hashes and roles live in deployment Secrets. Every service validates the principal; library mutations also require admin privileges.

`pdf_source.py` checks that an uploaded PDF is valid, unencrypted, within the byte/page limits and has page content. It does not extract or interpret text for new jobs. Scanned pages and arbitrary prompt formats are accepted. `models.py` defines PDF metadata, complete model-generated documents, character versions and semantic reviews. The old labeled source/edit contracts remain available to resume existing jobs.

`characters.py` owns the current Google Drive library. IDs and filename slugs do not change; descriptions/images increment versions. Edits require the current revision. An image replacement uploads a new image before publishing its document pointer, preserving a consistent reference through interruptions. Archiving/restoring changes selection visibility. Confirmed deletion removes only the current library folder.

`pipeline.py` snapshots the original PDF, its metadata, selected descriptions/versions, images and model settings in a recoverable job. The initial manifest embeds input bytes until all snapshot uploads finish. Reserved IDs precede every upload. The original PDF snapshot is checksum-verified and sent to the model for rewriting, review and correction. Attempt-specific checkpoints store the complete rewrite, candidate, independent AI review and validated final text. Resume reconciles checkpoints with the manifest after interruptions. Completed characters are skipped. Uncheckpointed AI responses may need another paid call.

`agents.py` sends the actual PDF as an Anthropic document block alongside all saved character properties and the PNG reference. Claude interprets the document's structure and returns the full adapted text through structured output. A separate review receives the same PDF and checks the complete adaptation, including saved traits, omissions, story, timings, dialogue, exact mappings and attachment filenames. One corrective rewrite is allowed. `replacement.py` checks nonempty output for new jobs; its deterministic source-block logic is retained only for legacy jobs. A human must accept production semantics.

`export.py` renders the model's full returned text using `fpdf2` with DejaVu and Noto/Ethiopic fallback fonts. Font cmap coverage is checked explicitly, so unsupported glyphs fail instead of being dropped. Text line order and explicit page breaks are preserved, with automatic wrapping and pagination; the source's exact visual layout is not reproduced. Each character's PNG uses the identical filename stem.

`storage.py` uses private app-created Google Drive folders and only `drive.file` OAuth access. Uploads reconcile pre-reserved IDs, names, parents, MIME types, and checksums. `job-manifest.json` records stage/status, attempts, reports, usage, UTC timestamps, creator, snapshots, and file IDs without credentials. Job dates use Africa/Addis_Ababa. ZIPs contain durable original/output files and validation reports, excluding checkpoints/snapshots.

The job gate allows one active job per process. New submissions save as pending. After a restart a user resumes explicitly; there is no background worker or distributed locking. The CLI uses the same parser, services, authentication, snapshots, and resume behavior and must not run concurrently with a hosted instance against the same root.

Automated tests inject failures before and after snapshot/checkpoint/output uploads and manifest completion updates. They also exercise hashed login/sign-out, admin restrictions, shared history, duplicate/stale-edit protection, character deletion, PDF round trips, Ethiopic, and real SDK serialization with local transports. Live provider/Drive/hosting acceptance requires configured credentials; see README.md.
